# 클로드 코드 안전 점검기 (cc-safety-check)

명령 한 줄로 이 컴퓨터의 클로드 코드 설정을 읽고, 사고가 나기 쉬운 빈칸을 1분 안에 보여 줍니다.

- **읽기만 합니다.** 설정 파일을 고치지 않고, 인터넷으로 아무것도 보내지 않습니다(코드에 네트워크 호출 0줄).
- 파이썬 3.8 이상, 표준 라이브러리만. 맥·리눅스에서 시험했습니다(윈도우는 아직 시험 전).

```bash
python3 -m pip install cc-safety-check
cc-safety-check --project /내/프로젝트/경로
```
설치 없이 파일 하나만 받아 써도 됩니다: `python3 cc_safety_check.py --project /내/프로젝트/경로`

## 무엇을 보나 (8문항)
| 문항 | 배점 | 점검 | 보는 곳 |
|:-|:-|:-|:-|
| A5 | 3 | 「확인 없이 전부 실행」 모드를 잠갔나 | `permissions.disableBypassPermissionsMode` (조직 관리 설정에 있으면 「예」, 개인·프로젝트 설정에만 있으면 「부분」) |
| B1 | 3 | 기본 권한 모드가 자동 승인이 아닌가 | `permissions.defaultMode` (공식 우선순위대로 뒤 설정이 이김) |
| A3 | 3 | 비밀 파일(.env · 키 파일) 읽기를 막았나 | `permissions.deny` 의 `Read(` 규칙과 `sandbox.filesystem.denyRead`(샌드박스가 켜져 있을 때만 셈). 둘 다 있으면 「예」, 하나만 있으면 「부분」. `Read(` 규칙은 읽기 도구에만 걸려 셸 명령(cat · 파이썬 한 줄)으로 읽는 길이 남고, 샌드박스 denyRead 가 그 길을 운영체제 수준에서 막습니다 |
| A4 | 3 | 위험 명령을 실행 전에 막나 | `permissions.deny` 의 Bash 규칙 · 실행 전 훅(훅만 있으면 「모름」) · 「모든 셸 명령 허용」 규칙 |
| C1 | 3 | 샌드박스를 켰나 | `sandbox.enabled` |
| D1 | 2 | 「끝났습니다」 전에 기계 확인을 거치나 | 마감 훅(Stop) (훅이 있으면 「모름」) |
| E2 | 2 | 같은 오류가 이어지면 멈추나 | 실행 뒤 훅(PostToolUse) · 실패 기록 훅(PostToolUseFailure) — 실패한 도구 호출은 PostToolUseFailure 로 따로 옵니다(둘 중 하나라도 있으면 「모름」) |
| A9 | 2 | 연결 도구(MCP 서버) 목록 | `~/.claude.json` · `.mcp.json` |

읽는 설정 파일: `~/.claude/settings.json` · `.claude/settings.json` · `.claude/settings.local.json` · 조직 관리 설정(`/Library/Application Support/ClaudeCode/managed-settings.json`, `/etc/claude-code/managed-settings.json`). 기본 권한 모드는 설정 파일 기준 우선순위(사용자 < 프로젝트 공유 < 프로젝트 개인 < 조직 관리)대로 뒤 설정이 이깁니다. 실행할 때 명령줄 옵션으로 바꾼 값은 파일에 없어서 보지 못합니다.
근거: 클로드 코드 공식 문서 [권한](https://code.claude.com/docs/en/permissions) · [설정](https://code.claude.com/docs/en/settings) · [샌드박스](https://code.claude.com/docs/en/sandboxing), OWASP 에이전트 응용 상위 10(2026판) ASI02 · ASI05.

답은 예 · 아니오 · 모름 · 부분 · 해당 없음 다섯 가지입니다. 점수(0.2.1): 「아니오·부분」 문항의 점수 합 ÷ (해당 없음·모름을 뺀) 문항 점수 합. 「모름」은 위험 비율에 넣지 않고 「확인 못 함 N개」로 따로 보여 줍니다. 3점 = 되돌릴 수 없는 손실 · 2점 = 복구는 되지만 크게 듦(A9 는 「모름」·「해당 없음」만 나와 위험 비율에는 들어가지 않음). 50% 이상이거나 3점 빈칸(아니오·부분)이 3개 이상이면 「높음」.

## 예시 — 만든 사람의 맥에서 돌린 결과
2026-11-23 · macOS 27.2.1 · Python 3.13.7 · 0.2.1 · 만든 사람 자기 맥 1대 결과입니다. 다른 컴퓨터 결과를 대표하지 않습니다.
```
위험 비율 75.0% · 구간 「높음」 · 3점 빈칸 3개 (A5, A3, C1) · 확인 못 함 3개 (A4, D1, E2)

먼저 고칠 3개
  · A3 비밀 파일(.env · 키 파일) 읽기를 막았다 → "permissions": {"deny": ["Read(./.env)", "Read(./.env.*)", "Read(~/.ssh/**)"]} · 셸 명령 읽기까지 막으려면 "sandbox": {"enabled": true, "filesystem": {"denyRead": [".env", "**/.env", "~/.ssh"]}}
  · A5 「확인 없이 전부 실행」 모드를 잠갔다 → 조직 관리 설정(managed-settings.json)의 "permissions" 안에 "disableBypassPermissionsMode": "disable" · 자동 모드까지 막으려면 "disableAutoMode"도
  · C1 샌드박스를 켰다 → "sandbox": {"enabled": true} · 세션에서는 /sandbox
```
같은 맥의 숫자가 판마다 달라진 것은 셈법을 고쳤기 때문입니다(설정은 그대로).
- 0.1.0(2026-11-10): 68.4%. 실행 전 훅만 있고 위험 명령 deny 규칙이 없는 A4를 「예」로 잘못 셌습니다.
- 0.2.0(2026-11-17): 84.2%. A4를 「모름」으로 고치고 「모름」도 위험에 넣었습니다.
- 0.2.1(2026-11-23): 75.0% + 확인 못 함 3개. 훅 내용을 못 읽어 「모름」인 문항(A4 · D1 · E2)은 위험 비율에서 빼고 따로 보여 줍니다. 「모름」을 위험에 넣으면 훅을 잘 짜 둔 설정도 늘 「높음」으로 나왔기 때문입니다.

## 한계 (숨기지 않습니다)
- 훅이 **있는지**만 봅니다. 훅 스크립트가 무엇을 확인하는지는 읽지 못해, 훅으로 판정하는 A4 · D1 · E2는 훅만 있으면 「모름」으로 표시하고 「확인 못 함」으로 셉니다. 위험 비율이 낮게 나와도 「확인 못 함」 문항은 `/hooks` 화면으로 직접 확인해야 합니다.
- 사람이 확인해야 하는 항목(깃 브랜치 보호 · 배포 승인 · 백업 복구 · 자료 기준)은 설정 파일 점검 범위 밖입니다.
- 설정 파일로 알 수 없는 것(실행할 때 옵션으로 바꾼 권한 모드 · 설치된 플러그인이 지금 켜져 있는지)은 클로드 코드의 `/status` · `/hooks` 화면으로 확인하세요.

## 자가 시험
```bash
python3 test_checker.py
```
시험용 설정 열세 가지에서 확인 37개를 봅니다(빈 설정 · 개인 설정에서만 잠금 · 넓게 연 설정 · 깨진 설정 · 조직 관리 설정이 이김 · 실행 전 훅만 있음 · 프로젝트 개인 설정이 위험 · .env 쓰기만 막음 · 휴지통 플러그인 훅 · Read 거부 규칙만 있음 · 샌드박스 denyRead 만 있음 · denyRead 는 있으나 샌드박스 꺼짐 · 실패 기록 훅만 있음). 설정은 임시 폴더에 만들어 돌리고, 내 컴퓨터 설정은 건드리지 않습니다. 「모름」을 위험 비율에서 빼고 「확인 못 함」으로 세는지 확인 2개도 함께 봅니다. 결과 37/37 (2026-11-23, 0.2.1).

## 0.2.1에서 고친 곳 (2026-11-23)
- 위험 비율: 「모름」을 분자·분모에서 빼고 「확인 못 함 N개」로 따로 표시. 3점 빈칸·구간·먼저 고칠 3개는 「아니오·부분」만으로 셈.
- A3: `Read(` 거부 규칙만 있으면 「예」 → 「부분」. 샌드박스를 켜고 `sandbox.filesystem.denyRead` 에도 비밀 경로가 있어야 「예」(Read 규칙은 셸 명령으로 읽는 길을 막지 못함). 고치는 법에 샌드박스 denyRead 예시 추가.
- E2: 실행 뒤 훅(PostToolUse)만 셌음 → 실패 기록 훅(PostToolUseFailure)도 셈. 고치는 법을 「실패 기록 훅으로 세고 실행 전 훅이 막게 묶기」로.
- 패키지 정보: 라이선스 표기를 SPDX 문자열("MIT")로 바꿈.
- 자가 시험 확인 28개 → 37개.

## 0.2.0에서 고친 곳 (2026-11-17)
- A4: 실행 전 훅만 있고 위험 명령 deny 규칙이 없으면 「예」 → 「모름」.
- A5: 조직 관리 설정에 있으면 「예」, 개인·프로젝트 설정에만 있으면 「부분」(점수에는 빈칸으로 셈). 고치는 법에 `disableAutoMode` 추가.
- 기본 권한 모드: 처음 찾은 값 대신 공식 우선순위대로 뒤 설정이 이김.
- A3: `Read(` 로 시작하는 deny 규칙만 셈(쓰기만 막으면 「아니오」).
- 휴지통(`.trash`)에 든 플러그인 훅은 세지 않음.
